El SDK oficial `@nekzus/liop` proporciona un conjunto de herramientas completo y fuertemente tipado para construir Clientes LIOP (Agent Nodes) y Servidores LIOP (Data Nodes) en TypeScript y JavaScript.

Si estás migrando desde el Model Context Protocol (MCP), la API te resultará muy familiar. LIOP fue diseñado para ofrecer una experiencia de desarrollo de **reemplazo directo** (drop-in replacement), abstrayendo la complejidad de Protobuf, WebAssembly y la red P2P bajo clases de TypeScript sencillas.

## Arquitectura del Paquete

El SDK se publica en npm como un único paquete que contiene tanto la lógica del Cliente como la del Servidor:

<CodeGroup>
```bash npm
npm install @nekzus/liop@latest zod
```
```bash pnpm
pnpm add @nekzus/liop@latest zod
```
```bash yarn
yarn add @nekzus/liop@latest zod
```
</CodeGroup>

<Note>
  Recomendamos instalar `zod` junto al SDK. Al igual que en la especificación MCP, LIOP utiliza Zod para garantizar que los argumentos de ejecución coincidan con el manifiesto de capacidades del servidor.
</Note>

## Arquitectura de Mínimas Dependencias (Instalaciones Opt-Out)

Por defecto, `@nekzus/liop` proporciona compatibilidad retroactiva directa con el Model Context Protocol (MCP) a través del módulo `LiopMcpBridge`. Para facilitar esta integración, el paquete declara `@modelcontextprotocol/sdk` como dependencia opcional y peer, por lo que las instalaciones estándar (`npm install @nekzus/liop`) la resuelven de forma automática.

Para entornos de producción restringidos (como contenedores Docker minimalistas, AWS Lambda o despliegues IoT) donde el espacio es crítico, es posible realizar una **instalación reducida de LIOP** omitiendo las dependencias opcionales:

<CodeGroup>
```bash npm
npm install @nekzus/liop@latest --no-optional
```
```bash pnpm
pnpm add @nekzus/liop@latest --without optional
```
```bash yarn
yarn add @nekzus/liop@latest --ignore-optional
```
</CodeGroup>

Esto reduce significativamente el tamaño de la instalación. El SDK utiliza `import()` dinámicos en su código interno, por lo que la lógica del puente MCP se carga únicamente si la aplicación la solicita.

## Compilación a WebAssembly con Component Builder

Aunque LIOP transmite módulos WebAssembly (`.wasm`) compilados a través de la red, los agentes pueden desarrollarse íntegramente en TypeScript.

El SDK incluye un puente de compilación nativo. Cuando un Agente TypeScript invoca `.execute()`, el SDK serializa el payload de JavaScript, lo empaqueta usando un motor similar a Javy en un módulo `.wasm` acotado y lo transmite a la malla a través de gRPC. Esto evita tener que escribir o compilar módulos Rust/Wasm de forma manual.

## Características de Seguridad y Rendimiento Enterprise

El SDK TypeScript mantiene paridad arquitectónica con el núcleo en Rust, asegurando restricciones Zero-Trust rigurosas:

- **Criptografía Post-Cuántica (ML-KEM-768):** Encapsulación asimétrica de extremo a extremo (`crystals-kyber`) y autenticación simétrica AES-256-GCM.
- **Transporte de Malla Híbrido:** Conexión P2P para Node.js y navegadores a través de WebSockets (WS) y oyentes libp2p TCP (Yamux).
- **Guardian-TS (Inspección AST Estática):** Mitigación proactiva de escapes del sandbox que bloquea capacidades no autorizadas del host *antes* de que se active la ejecución en `node:wasi`.
- **Listo para ZK-Receipt:** Soporte arquitectónico nativo para verificación criptográfica de ejecución frente a zkVMs.
- **Escalado Multi-Core (Pool de Workers):** Paralelización mediante `piscina`. Evita bloqueos en el bucle de eventos de V8 al delegar descifrado PQC, inspección AST y sandboxing WASI a hilos independientes a nivel de sistema operativo.

## Arquitectura de Workers Multi-Core

Bajo cargas computacionales intensivas, el SDK delega el procesamiento criptográfico y la ejecución de sandboxes a hilos independientes del sistema operativo mediante `piscina`, evitando bloqueos en el bucle de eventos.
